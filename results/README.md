# results/

Everything here is either **original measurements** (`raw/`) or **generated by a script** from them. Nothing is edited by hand. The phase-by-phase map (which board script made which raw folder, and which analysis script reads it) is in the top-level `README.md`, section "Where to Find the Results".

## Headline results

| File | Content |
| :--- | :--- |
| `phase5d/compare_configs.md` | A, B, B-iso and Config C (stock / tuned, with / without IPC) under `stress-ng` 0 / 50 / 100 % and all-core, one lateness definition (`L_rel`) for all. Charts: `wcl_by_tier.png`, `cdf_100.png`, `cdf_allcore.png`. |
| `phase6b/realload.md` | The same configs under realistic load (`rnet`, `rdeploy`, `rboth`), 2 repeats, with load evidence per run and the "Kernel work on CPU 3" table. Charts: `block_wcl.png`, `cpu3_kernel_work.png`. |
| `phase6b/drive.md` | Phase 6b full chain: every speed command checked at the emulated drive (lost / wrong / extra), delays from tick to drive. |

**File formats:** Linux files (`A_*`, `B_*`, `test*`, `real_r*/`, `linux_r*/`): one row per 10 ms cycle with `cycle, scheduled_ns, actual_wake_ns, lateness_ms, is_miss, …`. Config C: `C_*.csv` = DWT wake timestamps in 160 MHz cycles; `config_c_referee_*` = intervals measured by the referee board (row 0 is the gap before the first pulse and is excluded); IPC folders add `config_c_ipc_seq_*` (setpoint applied in each cycle) and `config_c_ipc_sender_*` (Linux send log); `act_*` folders add `config_c_act_*` (PWM writes) and `config_c_drive_*` (what board 3 saw). Lines starting with `#` are metadata. `env_*`, `counters_*`, `thermal_*`, `analytics_*` and `pc_traffic_*` files record the load, kernel counters, temperature and the PC traffic of each run.
